% 01-title. Centred text block over a full-width band of four marks.
%
% [plain]: no frametitle bar and no frame number on the title page.
%
% \PosterTitleBreak, not \inserttitle: the break belongs to this slide only.
% \inserttitle also feeds the short title, where a forced break would misbehave.
%
% THE MARK BAND is the reason the type above it is set tighter than it would
% otherwise be. Four marks at ~2cm need about 2.5cm of the 9cm page including
% their clearance, so every gap in the block came in. Do not open them up
% without taking the band back down — the two compete for the same page.
%
% TITLE SIZE is bound by the WIDTH of the second line, not by the page's
% height: "for NASA Reanalyses --- Colorado Snowpack" sets 14.1cm at 19pt
% against a 14.9cm text block, so 20pt overruns and trips Overfull \hbox.
% Measured off the render, not guessed. \fitline cannot help here — it
% measures a single line, and shrinking the two independently would leave a
% title set at two different sizes. If the wording changes, re-measure.
%
% Marks are SYMBOLS ONLY, no wordmark lockups: a lockup's cap height is a
% fraction of its bounding box, so at a shared height it reads as a whisper
% beside a solid disc, and sizing it to match makes it run half the page wide.
% Dropping the Claude wordmark for the starburst is what let all four go large.
%
% Heights are set per mark, not shared, because these four carry very different
% ink. The starburst is thin radial strokes and needs the most height before it
% matches a solid disc, which is why the meatball was originally set SMALLER
% than it — 1.95cm against 2.10cm.
%
% That is no longer the arrangement. The meatball is now the largest mark at
% 2.28cm and raised 0.22cm clear of the baseline the other three share. It costs
% page: the band grew 0.36cm, and every gap in the text block above came in to
% pay for it — the trade the note at the head of this file describes. Taking the
% meatball back down is what buys that space back if the type ever needs it.
%
% ORDER: the two hackweek HOSTS bracket the two TOOLS — NASA at the left, the
% Block W at the right, OpenAI and Anthropic between them. It ran hosts-then-
% tools (NASA, UW, OpenAI, Anthropic) until the marks were seen on the page.
%
% The two hosts are also raised off the baseline the two tools still sit on, so
% the bracketing reads in the vertical as well as the horizontal. The raises are
% NOT equal — meatball 0.22cm, Block W 0.36cm — because the two marks are not the
% same size, 2.28cm against 1.82cm. Equal raises would have aligned their bottoms
% and left the smaller W looking dropped; matching their tops outright needs
% 0.68cm and leaves a visible hole beneath it. 0.36cm splits the difference and
% brings the W's top to 2.18cm, just above the Anthropic starburst's 2.10cm.
%
% Tuned by eye against the render, which is the only way to set this: the marks
% are different shapes and no arithmetic on their bounding boxes says when a
% band looks level. Re-look if any height here changes.
%
% Raising the W is a position change, not a transformation of the mark, so it
% stays within the UW rules in graphics/logos/SOURCES.md — no rotation, no crop,
% no stretch, and still exactly one of height or width.
%
% \makebox to a fixed width with \hfill between, rather than four positioned
% nodes: the gaps then equalise themselves and stay equal when a height is
% retuned. Bottom alignment is \includegraphics's own baseline behaviour and is
% what a logo bar wants.
%
% The band sits IN THE FLOW under a \vfill, not as a page overlay. As an
% overlay it cost no vertical space — and so knew nothing about the text above
% it, which is how the Block W came to strike through the date line. In the
% flow the \vfill absorbs whatever is left over, so the two can never collide
% however the type or the mark heights are retuned, and if they ever cannot
% both fit the build fails on Overfull \vbox instead of overprinting.
